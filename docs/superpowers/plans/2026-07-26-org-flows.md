# Org Flows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Spec:** `docs/superpowers/specs/2026-07-26-org-flows-design.md`
**Depends on:** spec 6's implementation merged; backend spec 3 live (tests run against MSW).

**Goal:** The org switcher with soft-re-login semantics, create-org, the org-aware home with the invitation summons, and the claim-driven members page.

**Architecture:** Switching calls `POST /auth/token`, replaces the in-memory token, wipes every query cache, and lands on `/home`. Routes stay org-implicit (`/home`, `/members` mean the current org). What a viewer can do is rendered from the session's `permissions` (decoded from the access token); the API remains the enforcer and every client-side guard is mirrored by an error mapping.

**Tech Stack:** unchanged from plan 6.

## Global Constraints

- Plans 5–6 Global Constraints apply.
- Backend contract (exact): `POST /organizations` `{name}`; `GET /organizations` → `[{id, name, type, role}]`; `GET /organizations/{id}/members` → `[{userId, username, role, joinedAt}]`; `POST /organizations/{id}/invitations` `{inviteeUserId, role}`; `DELETE /organizations/{id}/invitations/{invId}`; `GET /invitations` → `[{id, organizationId, organizationName, role, inviterUsername, expiresAt}]`; `POST /invitations/{id}/accept|decline`; `PATCH /organizations/{id}/members/{userId}` `{role}`; `DELETE /organizations/{id}/members/{userId}`; `DELETE /organizations/{id}/members/me`; `GET /users?username=` → `[{id, username}]`; `POST /auth/token` `{organizationId}` → `{accessToken}` + rotated cookie.
- New error codes mapped (exact): `orgs.name-taken` → "That banner is already flown."; `orgs.quota-exceeded` → "You hold as many banners as the realm allows."; `orgs.last-owner` → "An organization must keep at least one owner."; `orgs.personal-immutable` → "Your personal keep cannot change hands."; `orgs.not-found` → "This hold is closed to you."; `invitations.already-pending` → "A summons is already on its way."; `invitations.expired` → "That summons has lapsed."; `orgs.owner-required` → "Only an owner may do that."
- Roles (exact strings): `OWNER`, `ADMIN`, `MEMBER`. Permissions relevant to rendering: `members.read`, `members.manage`, `org.manage`.
- Org name validation mirrors the backend: `[a-z0-9-]{3,30}`.
- New route (exact): `/members` inside the protected layout.
